ก่อนจะลงมือคำนวณ เราต้องเห็นภาพก่อนว่า “ผลลัพธ์” ที่เรากำลังจะสร้างหน้าตาเป็นอย่างไร

Decision Tree คือโมเดลจำแนกประเภท (classification model) ที่มีรูปร่างเป็นผังคำถาม แต่ละ internal node คือคำถามเกี่ยวกับ attribute หนึ่งตัว แต่ละ branch คือคำตอบที่เป็นไปได้ของคำถามนั้น และแต่ละ leaf node คือคำตอบสุดท้าย (class label)

หัวใจของบทเรียนนี้ คำถามที่ยากที่สุดในการสร้างต้นไม้คือ “ควรถามอะไรก่อน?” เพราะถ้าเลือกคำถามแรกผิด ต้นไม้จะใหญ่และแม่นน้อยลง บทเรียนนี้จะตอบคำถามนี้ด้วยเครื่องมือทางคณิตศาสตร์ชื่อ Entropy และ Information Gain

วงจรชีวิตของโมเดล มี 2 เฟส

เฟส 1 — Construction (Induction)

ป้อน training data ที่รู้คำตอบอยู่แล้ว แล้วให้อัลกอริทึม “งอก” ต้นไม้ขึ้นมาเอง โดยเลือกว่าแต่ละ node ควรถาม attribute ไหน
นี่คือเฟสที่ต้องคำนวณเลข และเป็นเนื้อหาหลัก §01–§05

เฟส 2 — Prediction

เอาข้อมูลใหม่ที่ ยังไม่รู้คำตอบ มาไหลลงจาก root ตามคำตอบของมัน จนตกถึง leaf — ค่าที่ leaf คือคำทำนาย
เฟสนี้ไม่มีการคำนวณเลย เร็วมาก — §06

01 ชุดข้อมูลฝึกสอน: ใครจะซื้อคอมพิวเตอร์?

ทุกเลขในบทเรียนนี้มาจากตารางเดียวนี้ทั้งหมด — ลองกดปุ่มด้านล่างเพื่อดูว่าแต่ละ attribute แบ่งข้อมูลออกเป็นกลุ่มอย่างไร

ข้อมูลมี 14 tuples (แถว) ประกอบด้วย attribute 4 ตัวที่ใช้ถาม และ class label 1 ตัวคือ buys_computer ซึ่งมี 2 ค่า (yes / no) จึงเรียกว่าปัญหา binary classification

แบ่งกลุ่มตาม:
ไฮไลต์ค่า:
# ageincomestudentcredit_rating buys_computer

สังเกตให้ดี ทั้งชุดข้อมูลมี yes 9 แถว และ no 5 แถว — ยังปนกันอยู่มาก ถ้าต้องเดาแบบไม่มีข้อมูลอะไรเลย เราจะเดาว่า “yes” และผิดประมาณ 5 ใน 14 ครั้ง เป้าหมายของการสร้างต้นไม้คือ แบ่งข้อมูลจนแต่ละกองเหลือคลาสเดียว เพื่อไม่ต้องเดาอีกต่อไป

02 เครื่องมือที่ 1 — Entropy: วัด “ความไม่เป็นระเบียบ”

ถ้าเราจะเลือกคำถามที่ดีที่สุด เราต้องมีไม้บรรทัดวัดก่อนว่า ข้อมูลกองหนึ่ง “มั่ว” แค่ไหน

สัญชาตญาณก่อนสูตร

ลองนึกถึงกล่อง 3 ใบ แต่ละใบมีลูกบอลสีเขียว (yes) กับสีแดง (no) ปนกันคนละสัดส่วน แล้วถามว่า “ถ้าหยิบมา 1 ลูกโดยไม่มอง คุณมั่นใจแค่ไหนว่าจะทายสีถูก?”

เขียวล้วน 10:0

ทายถูก 100% ไม่ต้องลุ้นเลย
Entropy = 0 (บริสุทธิ์ที่สุด)

เขียว 8 : แดง 2

ค่อนข้างมั่นใจ แต่ยังมีพลาด
Entropy = 0.722

เขียว 5 : แดง 5

เท่ากับโยนเหรียญ มั่วที่สุด
Entropy = 1 (สูงสุดเมื่อ 2 คลาส)

นิยามสั้นที่สุด Entropy = ปริมาณความไม่แน่นอน (uncertainty) ของข้อมูลกองนั้น — หรือถ้าจะพูดแบบ information theory: โดยเฉลี่ยต้องใช้กี่บิตในการบอกคำตอบของหนึ่งตัวอย่าง
Entropy สูง → มั่ว เดายาก  |  Entropy ต่ำ → เป็นระเบียบ เดาง่าย

สูตรทางการ

สำหรับตัวแปรสุ่มไม่ต่อเนื่อง Y ที่มีค่าเป็นไปได้ m ค่า คือ {y1, y2, …, ym}

H(Y)  =  − mΣi=1   pi · log2( pi )     โดย   pi = P(Y = yi) pi คือสัดส่วนของตัวอย่างที่อยู่ในคลาส i · ใช้ log ฐาน 2 หน่วยจึงเป็น “บิต” · กำหนดให้ 0·log₂0 = 0 (กองว่างไม่มีความไม่แน่นอน)

ทำไมต้องมีเครื่องหมายลบ?

เพราะ p อยู่ระหว่าง 0 ถึง 1 เสมอ ทำให้ log₂(p) ติดลบเสมอ เช่น log₂(0.5) = −1 การใส่ลบข้างหน้าจึงทำให้ค่า entropy ออกมาเป็นบวก — ไม่มีความหมายลึกซึ้งไปกว่านั้น

รูปร่างของ entropy เมื่อมี 2 คลาส (m = 2)

ลากแถบด้านล่างเพื่อเปลี่ยนสัดส่วนคลาส แล้วสังเกตว่า entropy พุ่งสูงสุดตอนสัดส่วน 50:50 และตกลงเป็นศูนย์ที่ปลายทั้งสองข้าง

ลงมือคำนวณจริง: Info(D) ของข้อมูลทั้ง 14 แถว

ในบริบทของ decision tree เราเรียก entropy ของชุดข้อมูล D ว่า Info(D) หรือ “จำนวนข้อมูลที่ยังต้องการเพิ่มเพื่อจำแนก tuple หนึ่งตัวใน D ให้ได้”

Info(D) = − mΣi=1 pi log2(pi)     โดย   pi = |Ci,D||D| |Ci,D| = จำนวน tuple ใน D ที่อยู่คลาส Ci  ·  |D| = จำนวน tuple ทั้งหมดใน D

แทนค่าทีละบรรทัด

pyes = 914 = 0.6429      pno = 514 = 0.3571

Info(D) = I(9, 5) = − 914 log2914  −  514 log2514

          = −(0.6429)(−0.6374) − (0.3571)(−1.4854)
          = 0.4098 + 0.5305 = 0.940 บิต
อ่านค่านี้อย่างไร 0.940 อยู่ใกล้ 1.0 มาก แปลว่าข้อมูลตั้งต้นของเรา เกือบมั่วที่สุดเท่าที่ 2 คลาสจะมั่วได้ นี่คือ “ระดับความไม่รู้เริ่มต้น” ที่เราจะพยายามลดให้ได้มากที่สุดในขั้นต่อไป

Conditional Entropy — entropy หลังจากที่เรารู้คำตอบของ X แล้ว

ถ้าเราได้รู้ค่าของ attribute X เพิ่ม ความไม่แน่นอนของ Y ควรจะลดลง ค่าเฉลี่ยของ entropy ที่เหลือหลังรู้ X เรียกว่า conditional entropy

H(Y | X) =  Σx   p(x) · H(Y | X = x) แปลเป็นภาษาคน: แยกข้อมูลเป็นกองตามค่าของ X → หา entropy ของแต่ละกอง → ถัวเฉลี่ยโดยถ่วงน้ำหนักด้วยขนาดกอง

แนวคิดนี้เองที่กลายเป็น InfoA(D) ในหัวข้อถัดไป

03 เครื่องมือที่ 2 — Information Gain: วัดว่า “คำถามนี้คุ้มแค่ไหน”

รู้แล้วว่าข้อมูลมั่วแค่ไหน ขั้นต่อไปคือวัดว่าถ้าถามคำถามหนึ่ง จะช่วยลดความมั่วลงได้เท่าไร

ขั้นที่ 3.1 — ถ้าแบ่งด้วย A แล้ว ยังเหลือความไม่แน่นอนเท่าไร?

สมมติเราเลือก attribute A ที่มีค่าเป็นไปได้ v ค่า การแบ่งจะได้ข้อมูล v กอง คือ D1, D2, …, Dv แต่ละกองมี entropy ของตัวเอง เรารวมเป็นค่าเดียวด้วยการ ถัวเฉลี่ยแบบถ่วงน้ำหนัก

InfoA(D) = vΣj=1  |Dj||D|  ×  Info(Dj) |Dj| / |D| = น้ำหนักตามขนาดกอง — กองใหญ่มีสิทธิ์ออกเสียงมากกว่า · Info(Dj) = entropy ของกองนั้น ๆ คำนวณด้วยสูตรเดิมจาก §02
ทำไมต้องถ่วงน้ำหนัก ถ้ากองหนึ่งมี 12 แถวและอีกกองมี 2 แถว การเอา entropy มาบวกกันเฉย ๆ แล้วหาร 2 จะทำให้กองเล็กมีอิทธิพลเท่ากองใหญ่ ซึ่งไม่ยุติธรรม — เราจึงชั่งด้วยสัดส่วนจำนวนตัวอย่างเสมอ

ขั้นที่ 3.2 — กำไรของข้อมูล (Information Gain)

เอา “ความไม่แน่นอนก่อนถาม” ลบด้วย “ความไม่แน่นอนหลังถาม” ส่วนต่างคือกำไรที่ได้จากคำถามนั้น

Gain(A)  =  Info(D)  −  InfoA(D) Info(D) = ความไม่รู้ก่อนแบ่ง  ·  InfoA(D) = ความไม่รู้ที่ยังเหลือหลังแบ่งด้วย A  ·  Gain(A) = จำนวนบิตของข้อมูลที่ A “ซื้อ” ให้เรา
กฎการตัดสินใจของ ID3 / C4.5 ที่ทุก node ให้คำนวณ Gain ของทุก attribute ที่ยังเหลือ แล้ว เลือกตัวที่ Gain สูงที่สุด มาเป็นคำถามของ node นั้น เพราะมันลดความไม่แน่นอนได้มากที่สุดต่อการถาม 1 ครั้ง — เป็นการเลือกแบบ greedy

สมบัติที่ควรรู้ 3 ข้อ

  • Gain ≥ 0 เสมอ — การรู้ข้อมูลเพิ่ม ไม่มีทางทำให้เรามั่วขึ้น (อย่างมากก็เท่าเดิม)
  • Gain = 0 หมายความว่า attribute นั้นแบ่งแล้วสัดส่วน yes:no ในทุกกองยังเหมือนเดิม → ถามไปก็ไม่ได้อะไร
  • Gain = Info(D) คือกรณีสมบูรณ์แบบ — แบ่งครั้งเดียวแล้วทุกกองบริสุทธิ์ ไม่ต้องถามอะไรต่ออีก

04 ลงมือจริง: หา Root Node ด้วยการคำนวณครบทั้ง 4 attribute

ตอนนี้ D = ข้อมูลทั้ง 14 แถว และเรารู้แล้วว่า Info(D) = 0.940 — มาดูกันว่า attribute ไหนคุ้มที่สุด

ดูการคำนวณของ:

เปรียบเทียบผลทั้ง 4 ตัว

เมื่อคำนวณครบทุก attribute ด้วยวิธีเดียวกัน จะได้ผลดังนี้ (แถบยิ่งยาว = ยิ่งดี)

สรุปผลการเลือก Root age ชนะขาด ด้วย Gain = 0.247 บิต สูงกว่าอันดับสอง (student, 0.152) อย่างชัดเจน ดังนั้น คำถามแรกสุดของต้นไม้คือ “age?” และต้นไม้จะแตกออกเป็น 3 กิ่งตามค่าของ age คือ <=30, 31…40, และ >40
หมายเหตุเรื่องการปัดเศษ — อย่าตกใจถ้าตัวเลขต่างจากสไลด์นิดเดียว หน้านี้คำนวณด้วยความละเอียดเต็มแล้วค่อยปัดตอนแสดงผล จึงได้ Gain(age) = 0.247 และ Gain(student) = 0.152 ส่วนสไลด์/ตำราแสดง 0.246 และ 0.151 เพราะนำค่าที่ปัดแล้วมาลบกัน (0.940 − 0.694 = 0.246) ทั้งสองแบบถูกต้องทั้งคู่และไม่กระทบลำดับการเลือก ซึ่งเป็นสิ่งเดียวที่อัลกอริทึมสนใจ — เวลาสอบให้ยึดวิธีที่อาจารย์ผู้สอนกำหนด แต่ต้องแสดงวิธีทำให้ครบเสมอ
เหตุผลเชิงสัญชาตญาณ ว่าทำไม age ถึงชนะ เพราะกลุ่ม age = 31…40 มี 4 แถวและ เป็น yes ทั้งหมด — entropy = 0 ทันที นั่นคือได้ “กองบริสุทธิ์” ฟรี ๆ หนึ่งกองจากการถามครั้งเดียว ไม่มี attribute ตัวไหนทำแบบนี้ได้เลย

05 Recursion: ทำซ้ำกับทุกกิ่ง จนกว่าจะหยุดได้

หัวใจของคำว่า recursive — ทุกกิ่งที่แตกออกมา คือปัญหาเดิมในขนาดที่เล็กลง

หลังแบ่งด้วย age แล้ว เรามีข้อมูล 3 กอง เราจะ ลืมข้อมูลนอกกองไปเลย แล้วทำกระบวนการ §02–§04 ซ้ำกับแต่ละกอง โดยมีข้อแม้สำคัญ: attribute ที่ใช้ไปแล้วบนเส้นทางนั้น จะไม่ถูกนำมาพิจารณาซ้ำ (ในที่นี้เหลือ income, student, credit_rating)

    06 ต้นไม้ที่ได้ และการนำไปทำนาย (Prediction)

    จบเฟส Construction แล้ว — นี่คือผลลัพธ์ และวิธีใช้งานจริง

    อ่านต้นไม้เป็นกฎ (IF–THEN rules) ต้นไม้ 1 ต้น แปลงเป็นชุดกฎได้ตรง ๆ โดยนับ 1 เส้นทางจาก root ถึง leaf = 1 กฎ ต้นนี้จึงได้ 5 กฎ:
    1. IF age ≤ 30 AND student = no → Not-buy
    2. IF age ≤ 30 AND student = yes → Buy
    3. IF age = 31…40 → Buy
    4. IF age > 40 AND credit_rating = fair → Buy
    5. IF age > 40 AND credit_rating = excellent → Not-buy
    ความอ่านออกได้นี้ (interpretability) คือจุดแข็งที่สุดของ decision tree เมื่อเทียบกับโมเดลอย่าง neural network

// D = ชุด training tuples ที่อยู่บน node นี้ พร้อม class label
// attribute_list = รายการ attribute ที่ยังไม่ถูกใช้บนเส้นทางนี้

1.  สร้าง node N

2.  if ทุก tuple ใน D อยู่คลาส C เดียวกัน then
        return N as leaf ที่ label = C          // หยุดเงื่อนไขที่ 1

3.  if attribute_list ว่างเปล่า then
        return N as leaf ที่ label = majority class ของ D   // หยุดเงื่อนไขที่ 2

4.  // ---- หัวใจ: เลือก attribute ที่ดีที่สุด ----
    splitting_attribute ← argmaxA ∈ attribute_list Gain(A)
    label node N ด้วย splitting_attribute
    attribute_list ← attribute_list − {splitting_attribute}

5.  for each ค่า aj ที่เป็นไปได้ของ splitting_attribute do
        Dj ← เซตของ tuple ใน D ที่มีค่า = aj
        if Dj ว่างเปล่า then
            แขวน leaf ที่ label = majority class ของ D     // หยุดเงื่อนไขที่ 3
        else
            แขวนผลของ GenerateDecisionTree(Dj, attribute_list) เป็นลูกของ N   // เรียกซ้ำ

6.  return N

    เงื่อนไขการหยุดแตกกิ่ง (stopping conditions) 3 ข้อ

    1. กองบริสุทธิ์แล้ว

    ทุก tuple ใน node อยู่คลาสเดียวกัน (entropy = 0) → ไม่มีอะไรให้แบ่งต่อ
    ตัวอย่างในบทนี้: กิ่ง age = 31…40

    2. attribute หมดแล้ว

    ถามครบทุก attribute แล้วแต่ยังปนกันอยู่ → ทำเป็น leaf แล้วใช้ majority voting

    3. ไม่เหลือตัวอย่าง

    กิ่งนั้นไม่มี tuple ใดตกลงมาเลย → ทำเป็น leaf โดยใช้ majority class ของ node แม่

    Majority Voting — เมื่อ leaf ไม่บริสุทธิ์

    ถ้าหยุดด้วยเงื่อนไขข้อ 2 หรือ 3 leaf จะยังมีทั้ง yes และ no ปนกัน วิธีกำหนด label คือ ให้คลาสที่มีจำนวนมากที่สุดชนะ เช่น leaf มี yes 4 / no 1 → label = yes และเราสามารถรายงานความเชื่อมั่นได้ด้วยว่า 4/5 = 80%

    ก้าวต่อไปหลังจากบทนี้ Information Gain มีจุดอ่อนคือ ลำเอียงเข้าหา attribute ที่มีค่าเป็นไปได้เยอะ ๆ (ลองนึกถึง attribute customer_id ที่แบ่งแล้วทุกกองบริสุทธิ์แต่ทำนายอะไรไม่ได้เลย) ทางแก้คือ Gain Ratio ใน C4.5 หรือใช้ Gini Index แบบ CART และยังมีเรื่อง overfitting / tree pruning ที่ต้องเรียนต่อ — แต่ทั้งหมดนั้นตั้งอยู่บนแนวคิดเดียวกับที่เพิ่งเรียนจบนี้

    08 ห้องทดลอง: คำนวณ Information Gain ด้วยตัวเอง

    เลือก node และ attribute แล้วระบบจะแสดงการคำนวณทุกบรรทัดให้ตรวจทาน — ใช้ฝึกทำโจทย์ด้วยมือแล้วมาเทียบคำตอบ

    node (ชุดข้อมูล D) attribute A
    แบบฝึกหัดที่แนะนำให้ลองทำด้วยมือก่อนกดดู
    1. ที่กิ่ง age <= 30 จงหา Gain ของ income แล้วอธิบายว่าทำไมจึงแพ้ student
    2. ที่กิ่ง age > 40 จงหาว่าทำไม Gain ของ income กับ student ถึงเท่ากันพอดี
    3. ที่กิ่ง age = 31…40 จงอธิบายว่าทำไม Gain ของทุก attribute จึงเป็น 0 และมันหมายความว่าอะไร

    สรุปทั้งบท: Decision tree สร้างด้วยการถามซ้ำ ๆ ว่า “คำถามไหนลดความไม่แน่นอนได้มากที่สุด” โดยวัดความไม่แน่นอนด้วย Entropy วัดความคุ้มค่าของคำถามด้วย Information Gain แล้วทำซ้ำแบบ top-down, recursive, divide-and-conquer จนเข้าเงื่อนไขหยุด
