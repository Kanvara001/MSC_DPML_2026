# Part I · บทความต้นฉบับ

## หน้า 4 · A ปัญหา ⏱ 1:00

เริ่มจากปัญหาที่บทความต้องการแก้ วิธีสร้างใบหน้าปลอมใหม่ ๆ เกิดขึ้นตลอด แต่โมเดลฝึกได้จากวิธีปลอมไม่กี่แบบ เช่น FF++ มี 4 วิธี ตัวอย่างในตาราง RECCE ฝึกบน FF++ ได้ AUC **97.91** แต่ Celeb-DF เหลือ **71.58** และ DFDC เหลือ **64.53**

บทความมองว่าสาเหตุอยู่ครบ 3 ขั้นของ pipeline ตามกล่องด้านล่าง คือ backbone จาก ImageNet ไม่มีความรู้เรื่องใบหน้า งานเดิมเพิ่มโมดูลแต่ไม่ได้พัฒนา backbone และใช้ threshold 0.5 ตายตัวค่ะ

## หน้า 5 · A ปัญหา → วัตถุประสงค์ → วิธี ⏱ 0:50

หน้านี้แยกสามเรื่องออกจากกันให้ชัด ขั้น pre-train ปัญหาคือ backbone ขาดความรู้เรื่องใบหน้า วัตถุประสงค์คือหา backbone ที่แทนลักษณะใบหน้าได้ดี วิธีคือ **FaceBEiT** ขั้น fine-tune ปัญหาคือ overfit วิธีคือ **CFB** ที่มี 2 backbone แข่งกัน และขั้น inference ปัญหาคือ threshold 0.5 วิธีคือ **UTOM**

ขอหมายเหตุว่าบทความไม่ได้เขียนเป็นคำถามวิจัยโดยตรง ตารางนี้ดิฉันเรียบเรียงจาก Section I และ III ค่ะ

## หน้า 6 · B ชุดข้อมูลของบทความ ⏱ 0:50

บทความใช้ข้อมูล 3 กลุ่ม pre-train ใช้ **ภาพใบหน้าจริง 550k ภาพ** ไม่มี label โดยไม่ระบุสัดส่วนแต่ละชุด fine-tune ใช้ **FF++ c23** วิดีโอจริง 1,000 ปลอม 4,000 และ evaluation มีทั้ง cross-dataset 5 ชุด ชุดภาพ 9 ชุดที่ผู้เขียนสร้างเองซึ่งไม่เผยแพร่ และ DF40 ซึ่งไม่ระบุจำนวนข้อมูลค่ะ

## หน้า 7 · B Distribution ⏱ 0:40

FF++ มี real ต่อ fake เป็น **1 ต่อ 4** แต่ละวิธีมี 1,000 วิดีโอเท่ากัน Celeb-DF test ตามรายชื่อทางการที่ repo ใช้มี 518 วิดีโอ จริง 178 ปลอม 340 ซึ่งบทความไม่ได้ระบุจำนวนนี้เอง ส่วน DFDC, DFDCP, DFD, FFIW และ DF40 บทความไม่ระบุสัดส่วน class ค่ะ

## หน้า 8 · B ร่องรอยการปลอม ⏱ 0:30

Fig. 4 แสดงว่าร่องรอยการปลอมมักอยู่ที่ส่วนประกอบของใบหน้า เช่น ซ้ำ หาย บิดเบี้ยว หรือรอยต่อสี จึงต้องการ backbone ที่เข้าใจใบหน้าในระดับ patch

## หน้า 9 · C ขั้นตอนเตรียมข้อมูล ⏱ 0:50

จากวิดีโอ เลือก **8 frame ระยะเท่ากัน** ตรวจหน้าด้วย **RetinaFace** align และ crop ปรับเป็น **224 × 224** แล้ว normalize ป้ายบนกล่องบอกว่าขั้นไหนมาจากบทความ ขั้นไหนมาจากโค้ด

ตารางด้านล่างแยกให้เห็นว่าบทความไม่ระบุวิธี align และขั้นตอนตอน test ส่วน repo มีโมดูล tracking จาก FTCN แต่**ไม่มีสคริปต์ประมวลผล FF++ ครบขั้น**

## หน้า 10 · C การแบ่งข้อมูล ⏱ 0:50

บทความ**ไม่ระบุ**การแบ่ง train / val / test ตัวเลขในตารางมาจาก split ทางการของ FF++ ที่อยู่ใน repo ซึ่งแบ่งตาม**คู่ identity** 360 / 70 / 70 คู่ หนึ่งคู่ให้วิดีโอจริง 2 และวิดีโอปลอม A→B กับ B→A ทุกวิธี identity จึงไม่ข้าม split

ข้อสังเกตสำคัญคือ บทความไม่กล่าวถึง validation และ repo ประเมินทุก epoch บน **test split** แล้วเก็บ checkpoint ที่ ACC สูงสุดค่ะ

## หน้า 11 · C Distribution หลังแบ่ง ⏱ 0:35

หลังแบ่ง ทุก split ยังเป็น 1 ต่อ 4 ไม่มีการ balance จำนวน frame ที่คาดคือวิดีโอคูณ 8 รวม 40,000 frame แต่ละ frame เป็น sample อิสระที่ใช้ label ของวิดีโอ จำนวนจริงที่ดิฉันเตรียมได้จะอยู่ใน Part II ค่ะ

## หน้า 12 · C Augmentation ⏱ 0:40

augmentation 7 แบบนี้มีในโค้ด บทความไม่กล่าวถึง ใช้**เฉพาะตอนเทรน** ส่วน val, test และ inference ทำแค่ resize กับ normalize ข้อสังเกตคือ HSV ±0.3 แทบไม่เปลี่ยน pixel และ Cutout ใช้กับทุกภาพ

## หน้า 13 · D ภาพรวม pipeline ⏱ 0:45

ก่อนลงรายละเอียด ภาพรวมคือ 3 ขั้นตาม Fig. 3 แถวล่าง **FB** คือ backbone ที่ pre-train บนใบหน้า **CFB** คือการ fine-tune ด้วย 2 branch และ **UTOM** คือการเลือก threshold ตอน inference ซึ่งใช้เฉพาะ main branch

## หน้า 14 · D เลือก backbone ⏱ 1:00

บทความเลือก backbone จาก Table I ซึ่ง fine-tune ทุกตัวบน FF++ ด้วย FC และ CE แบบเดียวกัน ค่าเฉลี่ย AUC ข้าม 3 ชุด ViT-B supervised **77.11** CLIP **81.92** BEiT v2 **82.70** BEiT ที่ pre-train บนหน้าล้วน **83.77** และ FB ที่เริ่มจาก ImageNet แล้วต่อด้วยใบหน้า **86.56**

in-set บน FF++ ได้ 97–99 ทุกตัว ความต่างจึงอยู่ที่ cross-set บทความไม่รายงาน std หรือจำนวนรอบ และดิฉันไม่ได้รัน Table I ซ้ำค่ะ

## หน้า 15 · D Face pre-training ⏱ 0:50

บทความบอกว่าใช้ MIM ตาม setting ของ BEiT v2 บน ViT-B และ A100 4 ตัวจนกว่าจะ converge แต่หลายอย่าง**ไม่ระบุ** เช่น สัดส่วนข้อมูล วิธีเลือก frame วิธี crop และ hyperparameter

หลักการคือปิดบาง patch แล้วให้โมเดลทาย visual token ของ patch นั้น repo มีเพียงนิยามโมเดลและ weight **ไม่มีสคริปต์ pre-train**

## หน้า 16 · D โครงสร้าง CFB ⏱ 1:10

CFB มี 2 backbone เริ่มจาก FB เดียวกันแต่**ไม่แชร์ weight** L_dec ตามสมการที่ 1 ลด correlation ระหว่าง [CLS] ของสอง branch โดยหยุด gradient ที่ main เพื่อผลัก auxiliary ให้ไปหาร่องรอยแบบอื่น

ด้านขวาคือ UFM ซึ่งให้น้ำหนักกับ branch ที่ uncertainty ต่ำกว่า แล้วรวม feature เป็น F ส่งเข้า head สมการในบทความเป็น softmax(−u) แต่โค้ดใช้ softmax(−10u) รายละเอียดอยู่ในภาคผนวก A4 ค่ะ

## หน้า 17 · D Loss ⏱ 1:00

loss รวมตามสมการที่ 9 มี 4 พจน์ คิดใน loss เดียวทุก step L_EDU ของ main และ aux ประกอบด้วย EDL กับ EUC และ CE ของ feature ที่รวมแล้ว รวมกับ L_dec

ด้านขวาคือทิศทางการ optimize ที่ดิฉันตรวจจากโค้ด **L_dec คืนค่า r ตรง ๆ** ไม่ใช่ |r| การ minimize จึงดันค่าไปทาง −1 ไม่ได้หยุดที่ 0 และ λ0 = 0.01 มาจากโค้ด บทความไม่ระบุค่ะ

## หน้า 18 · D วิธีฝึก ⏱ 0:45

ตารางเทียบสิ่งที่บทความเขียนกับ config ของผู้เขียน ตรงกันเรื่อง Lamb, learning rate 5e-5 แบบ cosine และ batch 64 ส่วน layer decay กับ weight decay มีเฉพาะใน config

**จุดที่ไม่ตรงกันคือ epoch** บทความเขียน 60 แต่ config เป็น 10 ทั้งนี้บทความเขียนด้วยว่า backbone ที่ pre-train บนหน้าจริง converge ใน 10 epoch

## หน้า 19 · D Inference และ UTOM ⏱ 0:55

ตอนใช้งานใช้เฉพาะ main branch คำนวณ p และ u ต่อ frame แล้วเฉลี่ย 8 frame UTOM ปรับเป็น **p′ = tanh(λp / 2(u+ε))** โดย λ = 0.02 จากนั้นหา τ ที่ให้ ACC สูงสุดบน cross-dataset ที่มี label **1 ชุด** แล้วใช้กับชุดอื่น repo **ไม่มีโค้ด UTOM** ค่ะ

## หน้า 20 · E Protocol และ metric ⏱ 0:40

บทความประเมิน 3 ระดับ คือ in-domain, cross-dataset และ cross-forgery โดยมี protocol 2 แบบ **generalization** ทดสอบทันทีหลังฝึก และ **adaptation** ปรับด้วยภาพไม่กี่ภาพ ตัวชี้วัดหลักคือ video-level AUC

## หน้า 21 · E ผลหลัก ⏱ 0:50

CFB ได้ FF++ **99.36** Celeb-DF **90.46** DFDC **84.90** FFIW 90.97 DFDCP 87.16 และ DFD 96.21 เฉลี่ย 5 ชุด 89.94 ใกล้ TFCU ซึ่งใช้ข้อมูลเชิงเวลา ขณะที่ CFB ใช้ภาพเดี่ยว

## หน้า 22 · E Cross-forgery ⏱ 0:45

บน 9 ชุดที่ผู้เขียนสร้าง CFB เฉลี่ย **83.86** สูงกว่า FB 81.90 และ BEiT v2 72.63 แต่ **StyleGAN3 ได้เพียง 60.75** บทความอธิบายว่าเพราะไม่เคยเห็นการสร้างทั้งหน้าและภาพสมจริงมาก ส่วน DF40 เฉลี่ย 96.22

## หน้า 23 · E Ablation และ threshold ⏱ 0:50

Table VI แสดงว่า L_dec เพิ่ม Avg. AUC จาก 87.04 เป็น 88.14 และครบทุกองค์ประกอบได้ 88.78 Table IX แสดงว่า UTOM เพิ่ม ACC เฉลี่ยจาก 80.13 ที่ τ = 0.5 เป็น **82.29**

ข้อควรสังเกตคือบทความไม่รายงาน ± หรือจำนวน seed และผลต่างระหว่าง variant บน Celeb-DF อยู่ที่ 0.16–1.28 จุดเท่านั้นค่ะ

## หน้า 24 · E Adaptation ⏱ 0:50

protocol adaptation คือปรับต่อด้วย 10 หรือ 20 ภาพ real และ fake เท่ากัน 2 epoch learning rate 2e-5 ส่วนวิธีเลือกภาพ batch และ optimizer บทความไม่ระบุ

ผลใน Table V เช่น Celeb-DF เพิ่มจาก 90.46 เป็น 91.33 DFDC จาก 84.90 เป็น 88.07 และ FFIW เป็น 96.65 ส่วน FF++ ลดลง 0.11–0.44 จุด บทความเรียกว่า "maintains stable performance" ซึ่งเป็นคำกล่าวของบทความค่ะ

## หน้า 25 · F ภาพรวมงานของเรา ⏱ 0:50

## หน้า 26 · F ข้อมูลที่เราใช้จริง ⏱ 0:40

ดิฉันใช้ 2 ชุดตามบทความ คือ FF++ c23 และ Celeb-DF v2 และเพิ่มอีก 2 ชุดที่**ไม่อยู่ในบทความ** คือ WildDeepfake และ DeepFakeFace ข้อควรระวังคือ DeepFakeFace เป็นภาพนิ่ง เทียบตัวเลขกับชุดวิดีโอตรง ๆ ไม่ได้ และภาพจริงมีภาพขาวดำ 11.9% ซึ่งอาจเป็นตัวกวน

## หน้า 27 · F การเตรียมข้อมูลของเรา ⏱ 0:40

จาก 5,000 วิดีโอ คาดว่าจะได้ 40,000 frame ได้จริง **39,999** ขาด 1 frame ที่ตรวจไม่พบใบหน้า คือ train Deepfakes 569_921 ภาพด้านบนคือผลการ crop วิดีโอ 071 กับวิดีโอปลอมทั้ง 4 วิธี

## หน้า 28 · F จุดที่ต่างจากต้นฉบับ ⏱ 1:10

ตารางนี้คือทุกจุดที่ต่างจากต้นฉบับพร้อมเหตุผล ขอเน้น 4 ข้อ

1. **Preprocessing** repo ไม่มีสคริปต์ครบขั้น จึงตรวจหน้าเฉพาะ 8 frame และใช้ IoU tracking หลักฐานว่าไม่กระทบผลคือ checkpoint ผู้เขียนผ่าน pipeline ของดิฉันได้ FF++ 99.24 และ CDF 90.05 ใกล้บทความ
2. **Pre-train** ใช้ weight ของผู้เขียน เพราะไม่มีสคริปต์และรายชื่อภาพ
3. **เลือก checkpoint จาก validation** แทน test เพื่อกัน test leakage และใน run นี้ได้ epoch 10 เหมือนกัน
4. **UTOM** เขียนจากสมการ และได้ ACC 85.33 เท่ากับ Table IX

## หน้า 29 · G การตั้งค่าการฝึก ⏱ 0:40

ดิฉันใช้ weight FB ของผู้เขียนและ hyperparameter ตาม DBBF.yaml ฝึก 10 epoch บน T4 สองตัว เพราะ VRAM 16 GB ไม่พอ จึงต้องใช้ AMP และ gradient checkpointing การฝึกใช้เวลาประมาณ 98 นาที

## หน้า 30 · G Learning curve ⏱ 0:40

validation AUC ของ fused head เพิ่มต่อเนื่องถึง **96.45** ที่ epoch 10 loss ลดเร็วใน 3 epoch แรก และ Pearson ระหว่าง 2 branch เปลี่ยนจาก +0.68 เป็นค่าลบ ผลบน FF++ test ด้วย main branch ได้ AUC **96.57**

# เตรียมตอบคำถามที่อาจถูกถาม

**Q1: ทำไมโมเดลที่ฝึกเองได้ต่ำกว่าบทความ**
ตัดเรื่อง preprocessing ออกได้ เพราะ checkpoint ผู้เขียนผ่าน pipeline ของดิฉันต่างจากบทความไม่เกิน 0.41 จุด ที่ยืนยันแล้วคือ seed เปลี่ยน AUC ได้ถึง 2.7 จุด ส่วน epoch 10 กับ 60 และ fp16 ยังเป็นสมมติฐาน (หน้า 31)

**Q1b: ทำไมไม่เลือก checkpoint จาก FF++ test ตามที่ repo ทำ**
test set ควรใช้วัดผลครั้งเดียวตอนจบ และ official split มี validation ให้อยู่แล้ว ใน run นี้ val AUC สูงสุดที่ epoch สุดท้ายจึงได้ checkpoint เดียวกัน (หน้า 28, 30)

**Q2: ablation กลับด้าน แปลว่าบทความผิดหรือไม่**
ยังสรุปไม่ได้ seed เปลี่ยน AUC ได้ 2.7 จุด มากกว่าผลต่างใน Table VI และบทความไม่รายงาน ± (หน้า 34–35)

**Q3: ทำไมใช้ AUC**
บทความใช้ video-level AUC ตามงานก่อนหน้า และข้อมูลมีสัดส่วน 1 ต่อ 4 AUC ไม่ขึ้นกับ threshold (เหตุผลข้อหลังเป็นการวิเคราะห์ของดิฉัน)

**Q4: Pearson ติดลบ ดีหรือไม่ดี**
L_dec ใช้ r ตรง ๆ ไม่ใช่ |r| จึงดันไปทาง −1 สอง branch จึงสัมพันธ์ทางลบ อาจไม่ใช่สิ่งที่ตั้งใจ (หน้า 17, A5)

**Q5: ทำไม UTOM ไม่ดีกว่า 0.5 ในการทดลองของเรา**
เมื่อย้ายข้าม dataset ที่สัดส่วน class ต่างกัน threshold ของ source ไม่จำเป็นต้องเหมาะกับ target บทความเองระบุใน Sec. IV-F ว่า class imbalance ทำให้ UTOM ไม่ robust (หน้า 32)

**Q6: ทำไมไม่ pre-train เอง**
ไม่มีสคริปต์, tokenizer, config และรายชื่อภาพ และประมาณการว่าต้องใช้ราว 450 ชั่วโมง GPU บน T4 (A10)

**Q7: few-shot รอบแรกมี run ที่ AUC ไม่เปลี่ยน เกิดจากอะไร**
ทั้ง 6 run เป็น k = 10 ซึ่งมีเพียง 4 optimizer step GradScaler ของ AMP ข้าม step ที่ gradient overflow weight จึงไม่ถูกอัปเดต เมื่อรันใหม่แบบ fp32 ทุก run อัปเดตได้ (หน้า 36)

**Q8: ทำไม few-shot ของเราทำให้ Celeb-DF ลดลง ขณะที่บทความเพิ่มขึ้น**
ยังเป็นสมมติฐาน: protocol ส่วนที่บทความไม่ระบุต่างกัน ดิฉันใช้ 1 frame ต่อวิดีโอและ batch 8 และ SD ระหว่าง run สูงถึง 2.25 จุด (หน้า 36)

**Q9: ตัวเลข UTOM ของบทความคือ 79.42 → 82.29 หรือ 80.13 → 82.29**
79.42 เป็น ACC ของ variant "+ L_dec" ใน Table VI ส่วน ACC ที่ τ = 0.5 จาก Table IX (CFB + L_EDU คอลัมน์ Avg.) คือ 80.13, τ_ot 80.63 และ τ_UTOM 82.29 (หน้า 23)
